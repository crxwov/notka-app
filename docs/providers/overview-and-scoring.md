# Параллельный поиск, дедупликация и скоринг треков

[← Аудио-стриминг и кэш](../backend/audio-streaming.md) · [К оглавлению](../README.md) · [Далее: Провайдеры YouTube →](youtube.md)

---

## Иерархия сервисов поиска

Сборка поискового ядра происходит в `music_resolver/services/factory.py` (`build_music_service()`):
1. **`MusicService` (`music_resolver/services/music_service.py`)** — внешний фасад с двумя in-memory TTL-кэшами (`search_cache` на 5 минут и `resolve_cache` на 15 минут).
2. **`ProviderManager` (`music_resolver/services/provider_manager.py`)** — оркестратор провайдеров. Определяет порядок приоритета источников:
   ```python
   PROVIDER_ORDER = ("youtube_music", "soundcloud", "youtube")
   ```
3. **`matcher.py` (`music_resolver/services/matcher.py`)** — модуль текстовой нормализации и расчёта релевантности каждого кандидата.

---

## Как работает поиск (`ProviderManager.search`)

1. **Параллельный опрос (`asyncio.gather`)**:
   - Запрос одновременно отправляется во все поисковые провайдеры (`youtube_music`, `soundcloud`, `youtube`) с индивидуальным таймаутом `PROVIDER_TIMEOUT_SECONDS` ($20\text{ с}$).
   - Если один из провайдеров упал или превысил таймаут, остальные провайдеры спокойно возвращают результаты.
2. **Дедупликация (`_deduplicate`)**:
   - Кандидаты из разных источников схлопываются по ключу:
     ```python
     (clean_text(artist), clean_text(title), round((duration or 0) / 3))
     ```
   - Благодаря порядку `PROVIDER_ORDER`, при совпадении трека приоритет всегда остаётся за версией из `youtube_music` (с качественной квадратной обложкой и привязкой к альбому/артисту).
3. **Ранжирование и срез `limit`**:
   - Каждый уникальный кандидат оценивается функцией `score_track(query, candidate)`, список сортируется по убыванию балла и обрезается до `limit`.

## Формула скоринга (`score_track` в `music_resolver/services/matcher.py`)

Функция `score_track(query, candidate)` вычисляет итоговый рейтинг кандидата из базового нечёткого совпадения (`rapidfuzz`), системы бонусов и штрафов за мусорные версии:

### 1. Нормализация текста (`clean_text`)
- Приводит строки к нижнему регистру, заменяет `ё` $\rightarrow$ `е`, очищает пунктуацию и схлопывает пробелы.
- Дополнительно формирует `title_core` — название трека без скобок `(...)` и `[...]`, чтобы приписки вроде `(Official Audio)` или `(feat. ...)` не занижали точность совпадения.

### 2. Базовый балл (`rapidfuzz`)
- `combined_score = 0.6 * token_set_ratio(query, artist + title) + 0.4 * partial_ratio(query, artist + title)`
- Дополняется весами совпадения чистого названия (`0.25 * token_set_ratio(query, title_core)`) и артиста (`0.15 * token_set_ratio(query, artist)`).

### 3. Бонусы качества
| Условие | Бонус | Назначение |
| :--- | :---: | :--- |
| Название трека или имя артиста точно совпадает с запросом (или начинается с него) | **$+25.0$** | Выводит точные совпадения на первое место. |
| `candidate.quality_hint == "ytm_song"` | **$+18.0$** | Отдаёт приоритет официальным студийным релизам из каталога песен YouTube Music перед клипами и перезаливами. |
| Наличие обложки `cover_url` и метаданных альбома | **$+12.0$** | Предпочитает треки с полноценным оформлением. |
| Известная длительность `duration` | **$+5.0$** | Отсекает битые стабы без метаданных. |

### 4. Штрафы за непрошенный мусор
Штрафы применяются **только тогда, когда сам пользователь не ввёл эти слова в поисковый запрос**:

| Категория | Слова-маркеры | Штраф |
| :--- | :--- | :---: |
| **`JUNK_WORDS`** | `live`, `concert`, `cover`, `кавер`, `karaoke`, `караоке`, `instrumental`, `минус`, `reaction`, `review`, `tutorial`, `разбор`, `8d`, `bass boosted`, `parody` | **$-35.0$** |
| **`VERSION_MODIFIERS`** | `slowed`, `reverb`, `sped up`, `nightcore`, `phonk remix`, `mashup`, `acoustic` | **$-22.0$** |
| **Слишком длинные записи** | Длительность $> 720\text{ с}$ (12 мин) / $> 480\text{ с}$ (8 мин) | **$-40.0$ / $-15.0$** |
| **Короткие огрызки / превью** | Длительность $< 35\text{ с}$ | **$-50.0$** |

## Фоллбэк при резолвинге (`ProviderManager.resolve_with_fallback`)

Если при попытке воспроизвести конкретный трек (`resolve`) основной провайдер вернул ошибку, `ProviderManager.resolve_with_fallback()` автоматически:
1. Формирует поисковый запрос `f"{track.artist} {track.title}"`.
2. Опрашивает остальные провайдеры из `PROVIDER_ORDER`.
3. Находит наиболее близкий рабочий трек по `score_track` и резолвит его поток, делая сбой незаметным для слушателя.
