# Нотка на постоянном сервере

Дома Нотка запускается через `start.bat` и живёт, пока включён компьютер, а
адрес меняется при каждом запуске. На сервере она работает круглосуточно по
постоянному адресу `https://<домен>/app/`.

## Что нужно

- **Сервер (VPS)**: Ubuntu 24.04, от 2 ГБ памяти, от 30 ГБ диска.
  Расположение — **не в России** (Нидерланды, Германия, Польша): с российского
  адреса каталог YouTube Music неполный.
- **Домен**, у которого A-запись указывает на адрес сервера.
- Ключ доступа: при создании сервера в панели хостинга добавить публичный
  ключ из `~/.ssh/notka_deploy.pub` (с домашнего компьютера).

## Первый запуск

С домашнего компьютера, из папки проекта:

```bash
# 1. подготовить сервер (один раз)
scp -i ~/.ssh/notka_deploy deploy/setup.sh root@<адрес>:/root/
ssh -i ~/.ssh/notka_deploy root@<адрес> "bash /root/setup.sh <домен>"

# 2. положить секреты (один раз): токен бота и адрес
ssh -i ~/.ssh/notka_deploy root@<адрес> "cat > /opt/notka/app/.env && chown notka:notka /opt/notka/app/.env && chmod 600 /opt/notka/app/.env" <<EOF
BOT_TOKEN=<токен от @BotFather>
PUBLIC_URL=https://<домен>
EOF

# 3. выложить код и запустить
bash deploy/push.sh <адрес>
```

## Обновление

После каждого сохранения изменений: `bash deploy/push.sh <адрес>`.

## Если что-то не так

```bash
ssh -i ~/.ssh/notka_deploy root@<адрес> "journalctl -u notka -n 80 --no-pager"   # последние сообщения Нотки
ssh -i ~/.ssh/notka_deploy root@<адрес> "systemctl status notka caddy --no-pager"
```

Бот не может работать в двух местах сразу: пока Нотка запущена на сервере,
`start.bat` дома запускать не нужно.

## Что на сервере иначе, чем дома

- Нет браузера с куками Google: треки YouTube с пометкой 18+ не играют, пока
  в `.env` не задан `YTDLP_COOKIE_FILE` с выгруженными куками.
- YouTube иногда требует «подтвердить, что вы не робот» с адресов
  дата-центров. Если так случится на выбранном хостинге, поможет другой
  хостинг или прокси (`YTDLP_PROXY` в `.env`).
- Аудио-кэш (до 2 ГБ) и тексты песен лежат в `/opt/notka/app/cache`.
