# Выпуск Нотки на сервер

Нотку совместно разрабатывают **leksik** и **hackov / Егор / crxwov**. Перед интеграцией или релизом прочитать [правила сотрудничества](../docs/operations/collaboration.md). Общая стабильная ветка — `main`; рабочие — `tg-app` и `app-dev`.

Основное руководство: **[docs/operations/deployment.md](../docs/operations/deployment.md)**. Проверенная инфраструктура и границы исследования: **[срез 14.10.2026](../docs/operations/infrastructure-2026-10-14.md)**.

## Текущая цель

- SSH: `ssh -p 6767 notka` (`egor@5.227.61.107`).
- Mini App: `https://notka.duckdns.org/app/`.
- Код/окружение: `/opt/notka/app`, `/opt/notka/venv`.
- Публичный nginx → Caddy → FastAPI; бот — дочерний polling-процесс.

После согласования и проверок владелец/назначенный разработчик релиза запускает из `main`:

```bash
bash deploy/push.sh 5.227.61.107
```

Push в main сам по себе не является деплоем. Агент не запускает эту команду по поручению обновить/закоммитить документацию.

`push.sh` отправляет **git archive HEAD**, устанавливает зависимости, перезапускает сервис и записывает DEPLOY_INFO. Незакоммиченные правки не отправляются. Защиту от смены ветки не обходить без согласования. Переменные NOTKA_SSH_USER/PORT/KEY позволяют явно выбрать доступ; старый IP 94.156.179.229 использует отдельные defaults root/5463.

## Остальные инструменты

- `setup.sh`: bootstrap чистой Ubuntu с доменом первым аргументом; не точная копия текущих сетевых настроек.
- `second_server_proxy.sh`: отдельный инструмент установки HTTP-прокси; не описание действующего sing-box/Hysteria.
- `yandex_relay.py`, `yandex_relay_install.sh`: отдельный relay для импортов; применять только по нужной задаче.

Куки YouTube владелец может передать боту файлом и проверить командой `/cookies`. Они применяются по требованию и являются секретом. Не запускать второй экземпляр polling-бота с production-токеном.
